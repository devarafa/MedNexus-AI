## 4. Internal Readiness Checklist

The following checklist may be used to track project readiness. It is not an official grading rubric.

### Documentation

- [ ] Proposal and scope are consistent.
- [ ] Requirements are documented.
- [ ] System design documents are complete.
- [ ] Technical documentation is updated.
- [ ] References and citations are consistent.
- [ ] Limitations and assumptions are documented.

### Implementation

- [ ] Core features are implemented.
- [ ] External integrations work as intended.
- [ ] API credentials are protected.
- [ ] Error handling is implemented.
- [ ] The application can be demonstrated.

### Testing

- [ ] Core functional workflows are tested.
- [ ] Invalid input and API failure cases are tested.
- [ ] Source links and retrieved metadata are checked.
- [ ] AI explanations are evaluated.
- [ ] Responsive behavior is tested.
- [ ] Conditional X-ray functionality is evaluated only if implemented.

### Presentation

- [ ] The project problem and objectives are explained.
- [ ] The architecture and technical choices are presented.
- [ ] Implemented features are demonstrated.
- [ ] Test results and limitations are explained.
- [ ] Experimental or incomplete features are clearly identified.
